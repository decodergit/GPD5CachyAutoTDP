# Проверка на устройстве (этап 4 плана)

Два скрипта: собрать метрики во время игры и разобрать их. Ничего в системе не меняют, только читают.

## 1. Сбор

```bash
cd /home/deck/homebrew/plugins/GPD5CachyAutoTDP
python3 tools/collect_metrics.py --seconds 300 --out /tmp/autotdp.csv
```

Запускать, когда игра уже идёт и Auto TDP включён. Скрипт пишет строку раз в секунду:

| колонка | что это |
|---|---|
| `t` | секунды с начала сбора |
| `tdp_w` | TDP из DPTC (или пусто, если backend только задаёт значение) |
| `fps` | FPS из самого нового `mangoapp_*.csv` |
| `temp_max` | максимум по датчикам CPU |
| `fan_pwm`, `fan_rpm` | ШИМ и обороты с контроллера GPD |
| `mangohud` | какой CSV читался |

MangoHud должен быть включён: без его CSV колонка `fps` будет пустой.

## 2. Разбор

```bash
python3 tools/analyze_metrics.py /tmp/autotdp.csv --target-fps 40
```

Выводит: число снижений и повышений TDP, их размеры, как часто TDP менялся, долю времени с FPS ниже цели, максимум и среднюю температуру, число изменений ШИМ и оборотов, провалы FPS после снижения TDP.

## Что считается нормой

- **Снижений TDP 5–10 за прогон**, а не десятки. Больше — значит поиск всё время перезапускается: скорее всего сцена часто меняется или цель недостижима.
- **Первый шаг вниз через 5–15 секунд** после того, как кадров стало с избытком. Дольше — проверьте `surplus_confirm_sec` в контроллере.
- **FPS ниже цели-2 не больше ~10–15 % времени.** Больше — цель выше того, что даёт железо при текущем лимите TDP.
- **Провалов FPS после снижения TDP нет или они короткие (1–2 с).** Длинные провалы означают, что пробы вниз слишком глубокие: уменьшите `max_probe_step_w`.
- **Изменений ШИМ заметно меньше, чем строк CSV.** Если ШИМ меняется почти каждую секунду — гистерезис не работает, проверьте `HYSTERESIS_C` и `PWM_DEADBAND_PCT`.
- **Обороты не «пилят»** между двумя значениями. Если пилят — увеличьте `HYSTERESIS_C`.

## 3. Проверка шейдерной компиляции

Запустите игру, которая компилирует шейдеры при первом старте (или очистите кеш). При включённом High-load TDP boost TDP должен подниматься ступенями, даже если FPS уже на цели. В CSV это видно как рост `tdp_w` при `fps` выше цели и высокой загрузке CPU.

Инструмент не пишет загрузку CPU/GPU: этих данных нет в sysfs в удобном виде. При необходимости смотрите их в самом плагине, строка CPU load / GPU load.
